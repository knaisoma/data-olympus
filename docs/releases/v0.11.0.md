# data-olympus 0.11.0

A minor release about the two gates the server puts in front of agents, and
about making both of them check what they say they check. The write pipeline
can now apply the project's writing rules to the documents agents write, and
the enforcement gate now clears a governed action only after a consult that
actually covered it. The release also publishes the server to the official MCP
Registry from the release workflow, fixes a REST status code that reported a
refused resolve as a success, and picks up security fixes in PyJWT and urllib3.
Upgrading is recommended for everyone, because of the dependency security fixes.
One default changes behaviour: read "Upgrading" before you deploy if your agents
rely on a single generic consult to clear every governed action.

## Added

### Writing rules on the documents agents write

The repository's own CI has rejected em-dashes, en-dashes used as em-dashes, and
agent authorship credit in its prose since 0.9.0. The documents agents write
into a knowledge base went through no such check. The write pipeline now applies
those raw rules to the lines a write adds, on every commit path: proposing a
memory, proposing an edit, resolving a pending proposal, and onboarding
bootstrap. (#283)

A write never fails on text it did not add. A line counts as added only when it
occurs more often in the postimage than in the target's current content, so
moving an existing line is not adding it, while a new offending line is always
caught, even when a different one is deleted in the same edit. A line ending in
`<!-- prose-lint: allow -->` is exempt and keeps the marker in the committed
text, so a genuine quotation stays visible as one.

`KB_WRITING_RULES_MODE` chooses what happens. `warn`, the default, commits the
write, returns the findings in `writing_rule_findings`, records the rule names
and line numbers (never the excerpts) in the audit event, and logs a warning.
`enforce` refuses the write as `rejected_writing_rule`, HTTP 422 on both propose
and resolve, with the findings in the same field; a refused resolve puts the
pending entry back. `off` skips the check. An unknown value fails startup.
`KB_WRITING_RULES_EXCLUDE_PATHS` skips paths by glob, matched like
`KB_WRITE_BLOCK_PATHS`.

The check runs after the secret scan, so a postimage carrying both a credential
and a finding is still reported as the redacted `rejected_secret_detected`. If
the check itself fails, including on an existing target that is not valid UTF-8,
it rejects in `enforce` and reports a warning in `warn`; it is never silently
skipped. The machine-rendered maintenance ledger is exempt, because it quotes
corpus ids and paths no agent wrote there; that exemption is reachable from no
MCP or REST call, and its audit event records the skip.

The vendored linter that holds these rules moved inside the package so the
installed server can import them. `scripts/prose_lint.py` remains as a shim, and
now needs the package installed: run it as
`uv run python scripts/prose_lint.py <path>`.

### The stable release publishes the MCP Registry entry

`server.json` has declared `io.github.knaisoma/data-olympus` since 0.8.0, but
the server was never listed in the official MCP Registry, because publishing as
a person requires public organization membership. The stable promotion workflow
now publishes the entry with GitHub OIDC after the GitHub release, from the
released source. It first checks that `server.json` names the released version
and that the release's PyPI description carries the ownership marker, runs a
pinned, hash-verified `mcp-publisher`, skips the publish when the version is
already listed, and reads the entry back. A registry outage cannot hold back
PyPI, the image or the GitHub release. (#303, part of #111)

## Changed

### A consult clears only the governed actions it covers

The enforcement gate used to allow any governed action after any fresh explicit
consult in the same session and workspace, whatever that consult had been about.
An agent could consult on a schema question and then run `pip install` without
having read the rules that govern dependencies. (#296)

Each consult now records the keywords, command fragments and paths its intent
names, and a governed action is allowed only when every one of its signals is
covered by a fresh consult. A small family mapping lets a topical consult cover
what it plainly governs: a consult about a dependency covers edits to dependency
manifests and install commands, and a consult about a schema or a migration
covers migration and SQL files. Coverage from several fresh consults combines,
and each part expires on its own TTL. Naming the action's own path or command in
the intent always clears it, so no governed action can become unclearable.

A denial still answers `consult_required`, so existing hooks keep working. Its
reason now lists the uncovered signals and suggests one intent that covers all
of them, and the `gate_block` audit event gains an `uncovered` field.
`docs/enforcement.md` describes the rule, the mapping and the migration.

### Other changes

- The CLI's dependency-free search fallback keeps its own copy of the path
  taxonomy. Tests now hold it to the index's copy: the same rules in the same
  order, and the same tier and category for every representative path, also
  with a custom `KB_TAXONOMY_PATH`. (#304)
- fastembed 0.8.1 for the optional embeddings extra. It fixes a path traversal
  in model archive extraction and a padding error on mixed-length batches.
  (#298)
- ruff 0.16.9 for development. (#297)

## Fixed

### REST resolve no longer answers 200 for an unknown decision

A `decision` other than `approve`, `reject` or `edit`, for example the typo
`aprove`, returned HTTP 200 with `status: rejected_bad_decision`, so a client
that checks only the status code read it as applied while the proposal stayed
pending. It now answers 400. A test pins the HTTP code of every status the write
tools can return, so a new status cannot fall through to a default unnoticed.
(#307)

### A bare trim-threshold tunable no longer undoes the 0.10.0 memory fix

The server leaves glibc's trim threshold alone when the operator has set it, and
it counted any `glibc.malloc.trim_threshold` entry in `GLIBC_TUNABLES` as such a
setting, including one with no value. glibc ignores a tunable without a value,
so under that malformed configuration nobody set the threshold and the memory
retention fixed in 0.10.0 came back. Only an entry with a non-empty value now
counts. (#302)

## Security

- PyJWT 2.15.1 (GHSA-r6x4-923q-g947, GHSA-w2cx-738m-mc7w, both high). 2.13.0
  could accept public key material, such as a JWK container or a BOM-prefixed
  key, as an HMAC secret. PyJWT reaches Data Olympus only through the MCP SDK,
  and Data Olympus does not call it directly.
- urllib3 2.8.0 (GHSA-8988-9cw3-xx77 and GHSA-vxq7-64xx-v4gw, high;
  GHSA-gh4c-6fx4-qh6g, medium): HTTPS proxy TLS settings could be ignored, and a
  chunked response could make the client buffer an unbounded line. urllib3
  reaches Data Olympus only through `requests`, used by the optional embeddings
  extra to download its model.
- cryptography 50.0.2, whose wheels are built against OpenSSL 4.0.3.

## Upgrading

- `KB_GATE_CLEARANCE` defaults to `intent`, the new rule above. An agent that
  consults once with a generic intent and then runs governed actions will be
  denied until it consults on what it is doing; the denial says what to consult
  on. Set `KB_GATE_CLEARANCE=pair` to keep the previous rule while you adjust.
  A session that consulted before the upgrade needs one new consult.
- `KB_WRITING_RULES_MODE` defaults to `warn`, which changes no write's outcome.
  Set `enforce` once a knowledge base has adopted these writing rules.
- Deployments with `KB_EMBEDDINGS_MODE=on` download the default embedding model
  once more after upgrading, because fastembed 0.8.1 resolves it to a repository
  name with different casing. A deployment without network access must refresh
  its model cache before upgrading, or startup fails with the model unavailable.
- Run the writing-rule linter as `uv run python scripts/prose_lint.py <path>`;
  the bare `python3` form needs the package installed in that interpreter.

See [serving.md](../serving.md) for both new settings.
