# data-olympus 0.11.0

A minor release about the two gates the server puts in front of agents, and
about making both of them check what they say they check. The write pipeline
can now apply the project's writing rules to the documents agents write, and
the enforcement gate now clears a governed action only after a consult that
actually covered it. The release also publishes the server to the official MCP
Registry from the release workflow, lets a document name the sources it was
derived from, records where a captured memory came from, moves to MCP SDK 1.30,
tightens several configuration and write-path checks, fixes a set of REST status
codes and error paths, and picks up security fixes in PyJWT and urllib3.
Upgrading is recommended for everyone, because of the dependency security fixes.
Several defaults and checks change behaviour: read "Upgrading" before you
deploy, especially if your agents rely on a single generic consult to clear every
governed action, or if your configuration sets `KB_AUTH_PRINCIPALS`,
`KB_SECRET_SCAN_EXTRA_PATTERNS`, `KB_READ_ONLY` or `KB_DISABLE_VERSION_CHECK`.

## Added

### Writing rules on the documents agents write

The repository's own CI has rejected em-dashes, en-dashes used as em-dashes, and
agent authorship credit in its prose since 0.9.0. The documents agents write
into a knowledge base went through no such check. The write pipeline now applies
those raw rules to the lines a write adds, on every commit path: proposing a
memory, proposing an edit, resolving a pending proposal, and onboarding
bootstrap. (#283)

A write never fails on text it did not add. A line counts as added only when it
occurs more often in the postimage than in the target's current content, so
moving an existing line is not adding it, while a new offending line is always
caught, even when a different one is deleted in the same edit. A line ending in
`<!-- prose-lint: allow -->` is exempt and keeps the marker in the committed
text, so a genuine quotation stays visible as one.

`KB_WRITING_RULES_MODE` chooses what happens. `warn`, the default, commits the
write, returns the findings in `writing_rule_findings`, records the rule names
and line numbers (never the excerpts) in the audit event, and logs a warning.
`enforce` refuses the write as `rejected_writing_rule`, HTTP 422 on both propose
and resolve, with the findings in the same field; a refused resolve puts the
pending entry back. `off` skips the check. An unknown value fails startup.
`KB_WRITING_RULES_EXCLUDE_PATHS` skips paths by glob, matched like
`KB_WRITE_BLOCK_PATHS`.

The check runs after the secret scan, so a postimage carrying both a credential
and a finding is still reported as the redacted `rejected_secret_detected`. If
the check itself fails, including on an existing target that is not valid UTF-8,
it rejects in `enforce` and reports a warning in `warn`; it is never silently
skipped. The machine-rendered maintenance ledger is exempt, because it quotes
corpus ids and paths no agent wrote there; that exemption is reachable from no
MCP or REST call, and its audit event records the skip.

The vendored linter that holds these rules moved inside the package so the
installed server can import them. `scripts/prose_lint.py` remains as a shim, and
now needs the package installed: run it as
`uv run python scripts/prose_lint.py <path>`.

### The stable release publishes the MCP Registry entry

`server.json` has declared `io.github.knaisoma/data-olympus` since 0.8.0, but
the server was never listed in the official MCP Registry, because publishing as
a person requires public organization membership. The stable promotion workflow
now publishes the entry with GitHub OIDC after the GitHub release, from the
released source. It first checks that `server.json` names the released version
and that the release's PyPI description carries the ownership marker, runs a
pinned, hash-verified `mcp-publisher`, skips the publish when the version is
already listed, and reads the entry back. A registry outage cannot hold back
PyPI, the image or the GitHub release. (#303, part of #111)

### Name the documents a guideline was derived from

A team guideline is often drawn from an upstream standard. When the standard is
retired, nothing told anyone that the guideline built on it needs a look. A
document can now declare `derived_from`, one concept id or a list of them. When
a source leaves force (excluded from the graph, `deprecated`, `superseded`,
`rejected` or expired), `kb_get` on the source names its in-force dependents in
`dependents_to_review`, `kb_get` on a dependent names its retired sources in
`derived_from_retired`, and `data-olympus lint` warns on both ends. `rejected`
counts as retired on purpose. `draft` and `proposed` never governed, so they do
not. (#300)

It is a cue for a person, not a rule the server applies: nothing is filtered,
demoted, ranked or invalidated, and `kb_search` and `kb_consult` are unchanged.
Lint reports a malformed or unresolved target as an error (`--unresolved-targets
warn` downgrades it), as well as self-reference, derivation cycles, and deriving
from a document the same document supersedes. The write path refuses a newly
introduced malformed or unresolved target, but never refuses a write because a
source retired. The format version moves to `0.5`, a backward-compatible
addition with no migration.

### Record where a captured memory came from

A memory distilled from a passive capture, such as a hook event or an external
transcript, can now carry a `capture` envelope on `kb_propose_memory` and its
REST route. `capture_source`, `capture_event_id`, `source_event_hash`,
`transformation` and `raw_retention` are required; `capture_session`,
`classification` and `derived_memory_hash` are optional, and the server checks
`derived_memory_hash` against the text it commits. The envelope holds
identifiers, hashes and enumerated values only, never the captured content.
(First slice of #141.)

The envelope is written to the memory's frontmatter, shown in the pending
listing and the readback, recorded in the committed and pending audit events,
and counted by the session recap as `capture_derived`. An operator edit at
resolve keeps it. It labels a memory, and grants nothing: it never forces
review and never puts a memory in force. An invalid envelope is refused as
`rejected_invalid_capture` (HTTP 400), and a credential-shaped value as
`rejected_secret_detected`.

## Changed

### MCP SDK 1.30

The server moves to MCP SDK 1.30.0 with Starlette 1.7.0, uvicorn 0.54.0 and
sse-starlette 3.5.0, and now requires `mcp>=1.30.0,<2` directly. The SDK closes
a streamable HTTP session that has had no request in flight for 30 minutes, and
holds at most 10000 sessions, answering HTTP 503 beyond that. An open SSE
stream keeps a session alive.

### Stricter checks on writes and configuration

- Onboarding bootstrap creates only new files under the workspace it onboards.
  Every target must lie under `projects/<workspace>/`, or under
  `projects/<workspace>/components/<component>/` when a component is given, in
  every onboarding state. Other paths are refused as
  `rejected_path_not_indexable_or_blocked`, and a target that already exists is
  refused at commit time as `rejected_already_onboarded`. Change an existing
  document with `kb_propose_edit`. The bootstrap commit subject now lists every
  path written.
- `kb_propose_edit` accepts `base_commit` only as `HEAD` (or `head`) or a commit
  id of 7 to 64 lowercase hex characters. Any other value is refused as
  `rejected_invalid_base` and is not recorded.
- A set but unusable `KB_AUTH_PRINCIPALS` stops startup with an error naming the
  setting and the entry number: invalid JSON, a value that is not a list, an
  empty list, or an entry that is not an object or has no non-empty `token`.
- `KB_SECRET_SCAN_EXTRA_PATTERNS` is parsed once at startup. It accepts a JSON
  array of patterns as well as the comma-separated form, which no longer splits
  a pattern at a comma inside `{...}` or `[...]`, so `ACME_[A-Z0-9]{20,40}`
  stays one pattern. An invalid or nested-quantifier pattern stops startup
  instead of being skipped.
- `KB_READ_ONLY` and `KB_DISABLE_VERSION_CHECK` accept `1`, `true`, `yes`, `on`,
  `0`, `false`, `no` and `off`, in any case, and stop startup on any other
  value. Previously an unrecognised value was read as off. (#314)

### Benchmark receipts for corpus changes

The benchmark receipt names the commit its numbers were measured at, and the
pull request check requires that commit to be on `main`, because a squash merge
drops branch commits. A change to a benchmark corpus could not satisfy it:
corpora are compared with the current tree, so the receipt must be re-measured
on the same branch. The check now also accepts a commit that a
`benchmarks/receipt-*` tag points at exactly, which keeps it resolvable after
the merge. This release's receipt uses `benchmarks/receipt-0.11.0`, because
the example bundle now declares format 0.5. `benchmarks/README.md` describes
when to use each route.

### Every path under `universal/` is tier T1

The default taxonomy classified seven `universal/` subdirectories, and any
other path there, such as `universal/README.md`, fell through to `meta`. Every
path under `universal/` is now T1. The seven keep their categories, other paths
get the category `universal`, and the CLI fallback matches. Search facets for
those documents move from `meta` to T1, and `KB_WRITE_BLOCK_TIERS=T1` now
covers the whole of `universal/`.

### A consult clears only the governed actions it covers

The enforcement gate used to allow any governed action after any fresh explicit
consult in the same session and workspace, whatever that consult had been about.
An agent could consult on a schema question and then run `pip install` without
having read the rules that govern dependencies. (#296)

Each consult now records the keywords, command fragments and paths its intent
names, and a governed action is allowed only when every one of its signals is
covered by a fresh consult. A small family mapping lets a topical consult cover
what it plainly governs: a consult about a dependency covers edits to dependency
manifests and install commands, and a consult about a schema or a migration
covers migration and SQL files. Coverage from several fresh consults combines,
and each part expires on its own TTL. Naming the action's own path or command in
the intent always clears it, so no governed action can become unclearable.

A denial still answers `consult_required`, so existing hooks keep working. Its
reason now lists the uncovered signals and suggests one intent that covers all
of them, and the `gate_block` audit event gains an `uncovered` field.
`docs/enforcement.md` describes the rule, the mapping and the migration.

### The enforcement report applies the same rule

`kb enforce report` and its `--staged` commit gate, the detection floor for
agents the gate cannot hook, now judge a governed commit by coverage too: the
explicit consults in the window must cover every signal of the commit's
governed paths. The `consult` audit event records the consult's `coverage` so
the report can tell. Audit rows written before this release carry no coverage,
so commits matched to them are judged by timing as before and reported as
`TIMING ONLY`. `KB_GATE_CLEARANCE=pair` keeps the old behaviour, and the report
reads the setting from the environment it runs in. (#309)

### Lint warns when frontmatter disagrees with the path taxonomy

The index honours a document's declared `tier` and `category`, while the write
blocklist (`KB_WRITE_BLOCK_TIERS`) classifies a write by its path. A document
under `universal/` that declares `tier: T4` was therefore listed as T4 but
governed as T1 for writes, and nothing said so. `data-olympus lint` now warns
on that disagreement and names the path value. It is a warning only, so an
intentional override still works. (#304)

### Other changes

- The CLI's dependency-free search fallback keeps its own copy of the path
  taxonomy. Tests now hold it to the index's copy: the same rules in the same
  order, and the same tier and category for every representative path, also
  with a custom `KB_TAXONOMY_PATH`. (#304)
- fastembed 0.8.1 for the optional embeddings extra. It fixes a path traversal
  in model archive extraction and a padding error on mixed-length batches.
  (#298)
- ruff 0.16.9 for development. (#297)

## Fixed

### REST resolve no longer answers 200 for an unknown decision

A `decision` other than `approve`, `reject` or `edit`, for example the typo
`aprove`, returned HTTP 200 with `status: rejected_bad_decision`, so a client
that checks only the status code read it as applied while the proposal stayed
pending. It now answers 400. A test pins the HTTP code of every status the write
tools can return, so a new status cannot fall through to a default unnoticed.
(#307)

### A bare trim-threshold tunable no longer undoes the 0.10.0 memory fix

The server leaves glibc's trim threshold alone when the operator has set it, and
it counted any `glibc.malloc.trim_threshold` entry in `GLIBC_TUNABLES` as such a
setting, including one with no value. glibc ignores a tunable without a value,
so under that malformed configuration nobody set the threshold and the memory
retention fixed in 0.10.0 came back. Only an entry with a non-empty value now
counts. (#302)

### Smaller fixes

- A session closed by the idle reaper stayed in the session table, so
  `live_sessions` in health never went down and the closed sessions were kept
  until restart. They now leave it.
- REST routes refuse a non-string value in a string field with HTTP 400 naming
  the field, and record nothing. Consult and record event could previously write
  such a value to the audit log, after which `kb_audit` and `kb_compliance`
  failed. Both now skip a malformed audit line and report it in a new `skipped`
  count. (#310)
- An empty bootstrap bundle is refused as `rejected_empty_bundle` (HTTP 400)
  before anything is claimed, committed or parked. It used to answer 500, or
  report a pending bootstrap that was never parked. (#311)
- Without `KB_REMOTE_URL`, the MCP tools `kb_list_pending`, `kb_get_pending` and
  `kb_audit` answer like their REST equivalents instead of failing with an empty
  tool error. (#312)
- REST resolve answers 400, not 200, when it refuses a symlink escape. (#313)

## Security

- PyJWT 2.15.1 (GHSA-r6x4-923q-g947, GHSA-w2cx-738m-mc7w, both high). 2.13.0
  could accept public key material, such as a JWK container or a BOM-prefixed
  key, as an HMAC secret. PyJWT reaches Data Olympus only through the MCP SDK,
  and Data Olympus does not call it directly.
- urllib3 2.8.0 (GHSA-8988-9cw3-xx77 and GHSA-vxq7-64xx-v4gw, high;
  GHSA-gh4c-6fx4-qh6g, medium): HTTPS proxy TLS settings could be ignored, and a
  chunked response could make the client buffer an unbounded line. urllib3
  reaches Data Olympus only through `requests`, used by the optional embeddings
  extra to download its model. Upstream notes that a
  configuration relying on destination TLS settings for an HTTPS proxy may need
  `proxy_ssl_context` instead.
- cryptography 50.0.2, whose wheels are built against OpenSSL 4.0.3.

## Upgrading

- `KB_GATE_CLEARANCE` defaults to `intent`, the new rule above. An agent that
  consults once with a generic intent and then runs governed actions will be
  denied until it consults on what it is doing; the denial says what to consult
  on. Set `KB_GATE_CLEARANCE=pair` to keep the previous rule while you adjust.
  A session that consulted before the upgrade needs one new consult.
- `KB_WRITING_RULES_MODE` defaults to `warn`, which changes no write's outcome.
  Set `enforce` once a knowledge base has adopted these writing rules.
- Deployments with `KB_EMBEDDINGS_MODE=on` download the default embedding model
  once more after upgrading, because fastembed 0.8.1 resolves it to a repository
  name with different casing. A deployment without network access must refresh
  its model cache before upgrading, or startup fails with the model unavailable.
- Startup now fails on configuration it used to ignore or misread: an unusable
  `KB_AUTH_PRINCIPALS`, an invalid `KB_SECRET_SCAN_EXTRA_PATTERNS` pattern, or a
  `KB_READ_ONLY` or `KB_DISABLE_VERSION_CHECK` value outside the accepted list.
  Check these settings before deploying; the error names the setting.
- An extra secret pattern containing a comma inside `{...}` or `[...]` is now
  one pattern, so it may match text it missed before.
- An onboarding bootstrap that wrote outside its workspace, or over an existing
  file, is now refused. Use `kb_propose_edit` for existing documents.
- The server now closes a streamable HTTP session with no request in flight for
  30 minutes, so a client idle that long must start a new session.
- Facets and `KB_WRITE_BLOCK_TIERS` treat every `universal/` path as T1. A
  deployment that blocks T1 writes now blocks those paths too.
- Documents may use `derived_from`; the format is `0.5`. Older documents need no
  change.
- Run the writing-rule linter as `uv run python scripts/prose_lint.py <path>`;
  the bare `python3` form needs the package installed in that interpreter.

See [serving.md](../serving.md) for both new settings.
